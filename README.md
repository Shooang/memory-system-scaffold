# memory-system-scaffold v3.0 (Knowledge OS)

为任意项目自动生成白盒化 Knowledge OS（知识操作系统）级分层记忆系统的 AI Skill。基于 AI 工作台五层架构工程实践，适用于 TRAE、Cursor、Codex、WorkBuddy、Claude Code 等所有支持本地 Skill 机制的主流 AI 工作台。具备目标锚定、注意力漂移防护、真相源仲裁、生命周期治理、主动自动更新、三级召回、结构化知识库等完整能力。

## 🚀 30 秒快速上手

### 方式 A：一键安装脚本（推荐）

从 GitHub clone 仓库后，在仓库根目录运行安装脚本：

```bash
# macOS / Linux
./install.sh

# Windows PowerShell
.\install.ps1
```

脚本会列出所有支持的 AI 工作台（TRAE / Cursor / Codex / Claude Code / WorkBuddy），交互式选择工具和安装模式（项目级 / 全局），自动复制必需文件到对应路径。

也支持参数模式直接指定：

```bash
./install.sh --tool trae              # 安装到当前项目 TRAE
./install.sh --tool cursor --global   # 全局安装到 Cursor
./install.sh --help                   # 查看帮助
```

### 方式 B：手动复制（无脚本环境）

把 `memory-system-scaffold/` 文件夹中的 `SKILL.md` 和 `README.md` 复制到目标工具的 Skill 目录：

- TRAE：`.trae/skills/memory-system-scaffold/`
- Cursor：`.cursor/skills/memory-system-scaffold/`
- Codex：`.codex/skills/memory-system-scaffold/`
- Claude Code：项目根目录（直接放）
- WorkBuddy：`skills/memory-system-scaffold/`

在 AI 对话中说：「搭建记忆系统」

## 核心设计理念

1. **白盒化管理**：资产存放在自己控制的目录，不绑定工具默认路径，工具（IDE/大模型/智能体）可随时替换
2. **目标锚定不漂移**：通过目标栈（长期→季度→阶段→当前任务）+ Checkpoint 机制，防止 AI 在长任务中偏离主线
3. **真相唯一不矛盾**：SoT（Source of Truth）L0-L6 权威层级，自动仲裁信息冲突
4. **存储服务于召回**：记忆不是存得越多越好，核心是「导航地图」——告诉 AI 什么时候读什么、读到什么颗粒度
5. **三级加载省 token**：默认 L1（TL;DR 摘要）→ 需要时 L2（相关片段）→ 深度时 L3（全文）
6. **生命周期自治理**：记忆有状态（valid/pending/deprecated），会衰老、冲突、合并，200 行强制去重
7. **主动更新不等待**：里程碑后主动提议记录，犯错即时记教训，新文件即时更新索引
8. **AI 自动分类**：用户定义顶层框架，具体文件分类、命名、内容整理交给 AI
9. **记忆与语料分离**：精炼规则放 memory/，大量参考资料放 context/（结构化子目录），记忆只留入口
10. **零配置开箱即用**：项目信息 AI 自动探测填充，无法探测的标记「待补充」

## v3.0 十大新功能（相对 v2.0）

1. **目标栈（Goal Stack）**：长期愿景→季度目标→阶段目标→当前任务四层分解，AI 每次回复前自动对齐检查，偏离时主动提醒
2. **Checkpoint 注意力防护**：长任务中每 3 步/10 轮自动输出进度检查点（目标/已完成/进行中/约束/侧线/下一步），检测到降智时主动建议新会话+交接摘要
3. **SoT 真相源层级**：L0 硬约束→L1 项目背景→L2 决策→L3 教训→L4 规范→L5 日志→L6 语料，7 级权威自动仲裁冲突
4. **记忆生命周期治理**：valid/pending/deprecated 三态管理、冲突检测、200 行强制去重合并、pending 7 天确认提醒、归档区
5. **主动自动更新**：里程碑后 `[记忆更新提议]` 等一轮确认；犯错/决策/新约束即时写入 pending；索引即时维护
6. **三级加载系统**：L1（TL;DR ≤500 tokens）/ L2（相关片段 ≤2000 tokens）/ L3（全文 ≤4000 tokens），明确升级触发条件和 token 预算
7. **增强导航地图**：增加优先级列（P0-P3）和召回预设标签；6 种任务类型→召回预设表；SoT 降级路由链
8. **结构化知识库**：context/ 分 5 个子目录（research/meetings/prd/courses/reference），每个语料文件强制元数据+AI 摘要+要点提炼，索引自动维护
9. **用户级记忆扩展**：preferences.md（偏好）/ knowledge.md（跨项目知识）/ lessons-learned.md（通用教训）
10. **统一文件模板**：所有记忆文件强制 TL;DR + 元数据表（last_updated/SoT等级/范围/状态）+ 状态标记 + 归档区

## 生成的文件结构

### 项目级记忆（必建）

```
<项目根目录>/
├── agent.md                     ← 项目全局规则（目标对齐/Checkpoint/自动更新/召回规则）
├── memory.md                    ← Knowledge OS 核心入口（目标栈+SoT+导航地图+召回预设+三级加载+生命周期）
├── memory/                      ← 具体记忆文件（每个含 TL;DR+元数据+状态标记）
│   └── log.md                   ← 工作日志（或 daily/ monthly/，按习惯选择）
└── context/                     ← 结构化知识库
    ├── README.md                ← 语料总索引（AI 自动维护）
    ├── research/                ← [按需] 研究/调研/竞品
    ├── meetings/                ← [按需] 会议纪要
    ├── prd/                     ← [按需] 需求文档
    ├── courses/                 ← [按需] 课程/学习资料
    └── reference/               ← [按需] 参考文档
```

### 用户级记忆（可选，跨项目通用）

```
<用户记忆根目录>/
├── agent.md                     ← 全局规则/人设
├── preferences.md               ← 输出偏好、语言、风格、交互习惯
├── knowledge.md                 ← 跨项目领域知识、思维模型、已知概念
└── lessons-learned.md           ← 通用经验教训、反模式
```

## 使用方法

### 初始化

触发后 AI 会：
1. 自动探测当前工作区的项目信息（名称/类型/定位/目标/技术栈等）
2. 询问搭建哪一层记忆（项目级/用户级+项目级/仅用户级）
3. 输出探测结果表格
4. 自动创建所有文件（不等待用户确认）
5. 汇报创建结果、待补充字段、目标栈状态、自动更新/Checkpoint/SoT 机制说明

### 日常使用

生成完成后，你的项目就拥有了一套完整的 Knowledge OS。以下是日常使用中最常用的操作：

| 你想做什么 | 你说什么 | AI 会做什么 |
|-----------|---------|------------|
| **更新目标** | 「更新目标」「这个阶段完成了」「进入下一阶段」 | 更新目标栈中的对应层级，记录变更历史 |
| **手动更新记忆** | 「更新记忆」「更新一下」 | 将近期未记录的工作沉淀到对应记忆文件 |
| **整理记忆** | 「整理记忆」「清理记忆」 | 去重/合并冗余条目、标记废弃、提炼摘要 |
| **导入存量资料** | 「扫描项目所有文档，初始化记忆系统和语料库」 | 全量扫描历史文档，提炼信息写入记忆+语料 |
| **检查进度** | （无需说，自动触发） | 长任务中每 3 步/10 轮自动输出 Checkpoint |

**自动发生的事（你不需要说）：**

- ✅ 完成里程碑后，AI 会主动说 `[记忆更新提议] ...`，等你确认后自动记录
- ✅ AI 犯错被你纠正，会自动写入经验教训（pending 状态）
- ✅ 做出重要决策，会自动写入决策日志（pending 状态）
- ✅ 长任务中自动输出 Checkpoint，防止偏离主线
- ✅ 检测到上下文饱和，主动建议开新会话并生成交接摘要
- ✅ 记忆文件超过 200 行，自动执行去重/合并/归档

## ❓ 常见问题（FAQ）

**Q: 我项目里已经有一些文件了，用这个 Skill 会覆盖吗？**
A: 不会。Skill 在生成前会检测是否已有 `memory.md` 或 `agent.md`，如果有会询问你是覆盖重建还是增量升级。

**Q: 我能只生成部分文件吗？比如我只想要记忆系统，不需要知识库。**
A: 可以。触发时你可以告诉 AI 你的需求，AI 会按需生成。或者生成后你自行删除不需要的目录（如 `context/`）。

**Q: 生成错了怎么办？能重来吗？**
A: 可以。直接说「重新生成」或删除已生成的文件后重新触发即可。所有文件都是纯 Markdown，没有隐藏状态。

**Q: 这个 Skill 需要付费吗？有什么使用限制？**
A: 完全免费、开源。你可以随意修改、分发、用于商业或非商业用途。唯一的限制是：不要用它来做违法的事。

**Q: 它支持哪些 AI 工具？**
A: 所有支持本地 Skill/技能机制的 AI 工作台都可以用，包括 TRAE、Cursor、Codex、WorkBuddy、Claude Code 等。纯 Markdown 格式，不绑定任何工具。

**Q: 我项目的内容很敏感，这个 Skill 会把我的数据传到哪里吗？**
A: 不会。所有文件都生成在你本地项目目录里，Skill 本身不含任何网络请求或数据上传功能。你的数据 100% 在你自己的电脑上。

**Q: 「pending」状态是什么意思？需要我手动改吗？**
A: pending 表示「待确认」。AI 自动记录的内容（如犯错、决策）默认标记为 pending，你明确说「对」「是的」「记住这个」后会自动转为 valid。你不需要手动改。

**Q: 生成的文件太多了，能精简吗？**
A: 可以。核心文件只有 3 个：`agent.md`（规则）、`memory.md`（索引+导航）、`memory/` 目录下的具体记忆文件。`context/`（知识库）和用户级记忆都是可选的，不需要可以删掉。

## Knowledge OS v3.0 铁律（生成的 memory.md 中自动写入）

1. `memory.md` 是入口：AI 每次对话先读 memory.md（L3 全文）
2. 目标栈是指南针：每次回复前检查目标对齐，偏离必提醒
3. Checkpoint 防漂移：长任务必须定期输出进度检查点
4. SoT 解决矛盾：信息冲突按 L0→L6 权威等级仲裁
5. 存储服务于召回：记忆是为了在正确场景找到正确信息
6. 三级加载省 token：默认 L1 摘要，按需升级 L2/L3
7. 导航地图比文件列表重要：告诉 AI「什么时候读什么、读到哪一级」
8. 元数据是基础设施：每个文件必须有 TL;DR + 元数据表
9. 记忆有生命周期：valid/pending/deprecated 三态，200 行强制去重
10. 决策必记原因：只记结果不记为什么等于没记
11. 自动更新不等待：里程碑主动提议，犯错即时记录，索引即时维护
12. 经验教训是执行前检查清单：执行前扫描相关教训
13. AI 自动分类：用户定义顶层框架，具体分类交给 AI
14. 不编造原则：无法探测的标记「待补充」，自动记录初始为 pending
15. 白盒化+防污染：资产自主可控，纯 MD 无绑定，不交叉污染
